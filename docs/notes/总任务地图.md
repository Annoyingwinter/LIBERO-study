# 总任务地图（8 周版，主线唯一）

> 本文件是唯一主线地图。任何会话从这里接手。
> 时间：每夜约 3 小时，共 8 周。
> 主线：可展示的 LIBERO 项目 = 可跑通的评测 pipeline + 真实成功率数字 + 失败案例分析。

## 1. 主线定义（写死，不再变）

```text
任务环境
  → 策略（先用占位策略，后换真策略）
  → 动作
  → 回合（reset → step → done）
  → 成功判定（env 自带的 _check_success）
  → 日志（每回合状态、步数、成功/失败）
  → 成功率统计（CSV + 数字）
  → 失败案例分析（扰动实验，5 档 × 10 初始状态）
```

可展示 = 三个数字能摆出来：

```text
1. 某任务在某策略下 N 个回合的成功率
2. 扰动幅度 → 成功率曲线
3. 至少 3 个失败案例的分类和解释
```

## 2. 必要性检验（每晚所有子问题的第一道闸）

```text
不搞懂这个，会不会卡住写评测 pipeline / 训练 / 评测？
  → 会卡住：限时深挖，到点记"当前最佳猜测 + 待验证"，继续走
  → 不会卡住：标"进阶选修"，进 进阶选修.md，不占主线时间
```

## 3. 8 周排程（每夜一个具体产出）

| 周 | 每夜产出主线 | 完成标志 |
|---|---|---|
| 1 | 评测 harness 骨架：20 回合占位策略跑通，出成功率数字（哪怕 0%）+ 每回合日志 CSV | harness 端到端可重跑 | ✅ 已完成（成功率 0/20，CSV 497B，day_eval_probe.py） |
| 2 | 成功判定打通：确认 `_check_success` 何时为真，人工构造 1 个成功回合 + 1 个失败回合 | 成功/失败各留日志 | ✅ 已完成（replay demo_0，第 80 步 done=True，1/1，day_replay_demo.py） |
| 3 | 接入真策略：选型（下载小 checkpoint 或训练 BC-RNN 小切片），跑通 1 回合推理 | 策略产出的动作能被 env 执行 |
| 4 | 正式评测：1 任务 × N 个 init state × 成功率 + 原始记录 | 成功率数字可重建 |
| 5 | 扰动实验：1 个扰动轴 × 5 档 × 10 初始状态 | 扰动→成功率曲线 |
| 6 | 失败案例分析：至少 3 类失败，写清"现象→原因→证据" | 案例文档 |
| 7 | 展示收口：README + 一键复现命令 + 结果图表 | 他人能按 README 重跑 |
| 8 | 缓冲 + 线性代数论文组装（用已有 CSV 数据，不新学理论） | 论文初稿 |

策略选型放在第 3 周，是因为：
- 评测 harness 与"策略是谁"无关，先用占位策略（手写反馈规则）就能建；
- 真策略的下载/训练需要网络和兼容性确认，不能卡住第 1 周的产出。

## 6. 交接规则（不变）

1. 场景先行，犯错先反问两次再给答案。
2. 能解释每步"为什么"才算掌握。
3. 混乱时用解锁句 + 3 个真懂才能答的问题。
4. 一切结论要数字，写进 day1_lab_notes.md。
5. 不升级依赖、不下载数据集、不训练模型——除非为第 3 周策略选型单独批准。
6. 相机/渲染不是重点。
7. 每晚开始先报产出，结束时报完成/未完成。
